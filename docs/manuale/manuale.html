1. Cos'è il progetto

NewBoxofficeProject raccoglie ogni settimana la classifica del box office italiano da ComingSoon.it, collega ogni film alla scheda TMDB (movie_id) e salva tutto in PostgreSQL. I KPI vengono poi esportati verso il sito vetrina (repository separato boxoffice-site).

ComingSoon → weekly_run → PostgreSQL → resolve_matches (TMDB) → health_check → export KPI → sito

Tutti i comandi si lanciano da PowerShell nella cartella radice del progetto, con il virtualenv attivo (o usando .venv\Scripts\python.exe).

2. Prerequisiti e installazione

  • Windows con PowerShell, Python 3.14 e PostgreSQL 18 in locale.
  • Un account TMDB (token di lettura o chiave API).
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt

Prima configurazione (una tantum)

python scripts/manage_secrets.py import-env --strip      # sposta gli eventuali segreti di .env nel deposito
python scripts/setup_db_roles.py --database boxoffice    # crea i ruoli, i privilegi e le password
# poi imposta DB_USER=boxoffice_app in .env
python scripts/migrate.py                                # crea/aggiorna lo schema
python scripts/manage_secrets.py set tmdb_read_token     # chiede il token senza mostrarlo

3. Configurazione e credenziali

Copia .env.example in .env. Il file contiene solo valori non segreti.

VariabileUso
DB_HOST, DB_NAME, DB_USERObbligatorie (es. localhost, boxoffice, boxoffice_app)
DB_PORT, LOG_LEVEL, REQUEST_TIMEOUTOpzionali, hanno un valore predefinito
DB_OWNER_USER, DB_RO_USERNomi dei ruoli owner (migrazioni, backup) e sola lettura (controlli)

Password e chiavi API stanno nella Gestione credenziali di Windows (servizio NewBoxofficeProject). Le variabili d'ambiente DB_PASSWORD, TMDB_API_KEY, TMDB_READ_TOKEN hanno la precedenza, e servono alla CI.

Per sperimentare senza toccare i dati reali usa boxoffice_dev (va creato a mano con CREATE DATABASE e inizializzato con migrate.py):

5. Flussi di lavoro tipici

Routine settimanale (manuale)

python main_v3.py
python scripts/health_check.py
python scripts/verify_db.py

Revisione dei match dubbi

Un film è abbinato in automatico se il punteggio è ≥ 0.85 con almeno 0.10 di margine sul secondo candidato. Tra 0.55 e la soglia va in revisione; sotto è "senza match".

python scripts/resolve_matches.py --review                 # trova l'ID del film e i candidati
python scripts/resolve_matches.py --set 2 --tmdb-id 920    # conferma il candidato giusto
python scripts/resolve_matches.py --no-match 28            # oppure: non esiste su TMDB

Recupero di una settimana persa

python scripts/recover_from_wayback.py --dry-run
python scripts/recover_from_wayback.py
python scripts/resolve_matches.py

Prima di un'operazione rischiosa

python scripts/backup_db.py --label prima_di_x
python scripts/migrate.py --status

Interrogare i dati

La vista v_weekly_enriched unisce classifica, film TMDB e stato del match ed è il punto di accesso consigliato per report e query.

SELECT rank, external_movie_title, tmdb_title, weekly_gross, gross_per_screen
FROM v_weekly_enriched
WHERE week_start = (SELECT max(week_start) FROM weekly_box_office)
ORDER BY rank;

6. Esecuzione pianificata e notifiche

ComingSoon non ha archivio: una settimana non caricata non si recupera facilmente, quindi la pipeline va eseguita ogni settimana. L'attività pianificata parte il lunedì e il venerdì alle 12:00 (il venerdì è una rete di sicurezza se il PC era spento). L'upsert è idempotente: rieseguire non crea duplicati.

  • Gira come l'utente corrente solo con la sessione aperta; se il PC era spento parte appena possibile.
  • I log sono in logs/ e si cancellano dopo 90 giorni.
  • Se la pipeline fallisce o l'health check trova un FAIL: notifica desktop di Windows e, facoltativamente, webhook (compatibile Slack/Discord) impostabile con python scripts/manage_secrets.py set notify_webhook_url.
  • Il codice di uscita compare come "Ultimo risultato" nell'Utilità di pianificazione.

8. Risoluzione dei problemi

SintomoCosa fare
Errore "migrazioni da applicare"Lancia python scripts/migrate.py. L'applicazione non esegue DDL.
Health check in FAILLeggi il messaggio: pipeline ferma o dati incoerenti. Controlla l'ultimo log in logs/. I soli WARN (es. settimane storiche già perse) non sono guasti.
Settimana mancanteProva recover_from_wayback.py; Wayback ha pochi snapshot, non tutte le settimane sono recuperabili.
resolve_matches.py esce con 1La connessione al database è caduta a metà elenco: rilancia il comando, riprende dai film rimasti.
Errore sul deposito credenzialiVerifica con manage_secrets.py list che il segreto esista; controlla di essere nella sessione utente corretta.
Nessuna notifica ricevutaLa notifica desktop funziona solo a sessione aperta; per il webhook controlla notify_webhook_url.
Un film ha un [errore] nel resolverÈ un guasto TMDB o dati di quel solo film: gli altri proseguono. Riprova con --retry.

9. Limiti da conoscere

Niente archivio storico. ComingSoon serve sempre la classifica corrente e ignora le date: il backfill (backfill_historical_weekly.py) carica solo le settimane davvero presenti nella pagina. Lo storico si costruisce eseguendo la pipeline ogni settimana.
  • Lo schema si modifica solo con nuove migrazioni in migrations/; una migrazione già applicata non va mai modificata (il checksum è verificato).
  • Non usare Box Office Mojo come fonte alternativa: il suo robots.txt vieta l'accesso automatico.
  • Il deposito credenziali non protegge da un programma malevolo eseguito con il tuo stesso account.
  • Retention: backups/ 30 giorni (min. 3 dump), log 90 giorni; le tabelle di audit (ingestion_runs, raw_snapshots, quarantena) si conservano indefinitamente.
